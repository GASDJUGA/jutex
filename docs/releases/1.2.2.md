LibreTeX opens again the way it was closed, the file tree and the outline fold with an animation, and fixes to the math preview, the PDF viewer, menus and the flicker on Linux.

## Install

- **Arch Linux:** `sudo pacman -U libretex-1.2.2-1-x86_64.pkg.tar.zst`
- **Other Linux distributions:** `chmod +x LibreTeX_1.2.2_amd64.AppImage` and open it.
- **macOS (Apple Silicon, 13 or later):** open `LibreTeX_1.2.2_aarch64.dmg` and drag LibreTeX to Applications. It isn't signed by Apple, so macOS blocks it the first time: on macOS 15, System Settings → Privacy & Security → «Open Anyway»; on 13 and 14, right-click the app → Open.
- **Windows 11 (x64):** run `LibreTeX_1.2.2_x64-setup.exe` (it installs for your user, without administrator rights). It isn't signed: if SmartScreen warns you, «More info» → «Run anyway».

Download from another machine: `gh release download v1.2.2 -R GASDJUGA/jutex`

Update by installing over 1.2.1; projects and settings are kept.

## What's new since 1.2.1

### On all platforms

- **Comes back the way it was closed:** LibreTeX opens with the same size, maximized or in full screen as it was (also if it was closed while minimized, from the taskbar), and on the project that was in view instead of on Home. Full screen comes back on the same monitor; a normal or maximized window goes where the system puts it (on Linux with Wayland, the desktop picks the monitor).
- **Folding shows:** when folding or unfolding a folder of the file tree or a section of the outline, its contents shrink or grow and fade, instead of vanishing at once (with the system's «reduce motion», instantly).

## Fixes

- **Math preview with primes:** a prime right before the parenthesis of a physics function (`\cos(\omega t')`, `\div(J(r',t'))`) no longer breaks the formula. It was a bug in MathJax 4.1.3, fixed with a patch in LibreTeX.
- **Typing with a long PDF open** no longer lags behind the keyboard: the viewer (pdf.js) rearranged every text layer of the PDF on each key, and in WebKit (Linux and macOS) every viewer replaced when compiling or zooming stayed alive in memory.
- **With two windows,** selecting text in one while the other had something selected no longer makes the selection flicker.
- **Copy of a project:** it shows first in «Recently opened» (it used to be last, because it had never been opened).
- **Menus:** when one (File, Edit…) is opened with the mouse, its first option is no longer highlighted as if the pointer were over it; opened with the keyboard it is, to go through it with the arrow keys.

## Linux: the WebKitGTK 2.54 flicker

With WebKitGTK 2.54 and NVIDIA the screen went back to an earlier frame for a while: a line just typed came and went, or the outline flickered under the pointer. 1.2.1 blamed NVIDIA driver 615, but it still happened with 620. Now LibreTeX turns off WebKit's damage tracking (redrawing only what changed) in every window, which is what showed those old frames.

## Known issues

- **Linux (WebKitGTK 2.54, NVIDIA):** when coming back to the window, the active line sometimes flickers for a moment (~0.3 s) between the old one and the new one. The page doesn't change: it's the screen.
- **Linux:** when typing an accent with a dead key (´ + o), WebKitGTK shows a frame without the accent or the letter; if the line is right at the edge of the window, it looks like a short jump.
