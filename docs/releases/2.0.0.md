**LibreTeX is now called JuTeX** (_Just a TeX editor_). It's the same app, the next version after LibreTeX 1.2.2: the name changes because another editor called LibreTeX already exists. The first time it opens, JuTeX brings over everything from LibreTeX by itself: nothing to export or set up.

## Install

- **Arch Linux:** `sudo pacman -U jutex-2.0.0-1-x86_64.pkg.tar.zst` (replaces the `libretex` package).
- **Other Linux distributions:** `chmod +x JuTeX_2.0.0_amd64.AppImage` and open it.
- **macOS (Apple Silicon, 13 or later):** open `JuTeX_2.0.0_aarch64.dmg` and drag JuTeX to Applications. It isn't signed by Apple, so macOS blocks it the first time: on macOS 15, System Settings → Privacy & Security → «Open Anyway»; on 13 and 14, right-click the app → Open.
- **Windows 11 (x64):** run `JuTeX_2.0.0_x64-setup.exe` (it installs for your user, without administrator rights). It isn't signed: if SmartScreen warns you, «More info» → «Run anyway».

Download from another machine: `gh release download v2.0.0 -R GASDJUGA/jutex`

## Moving from LibreTeX to JuTeX

**Close LibreTeX before opening JuTeX for the first time.** On startup, JuTeX moves to its new folders:

- the settings, the project list and the personal dictionary;
- the TeX Live you installed from the app (no need to install it again) and the cache;
- what the window remembered: open tabs, the cursor of each file, the PDF page, the panel sizes and the window maximized or in full screen;
- in each project, the hidden `.libretex/` folder becomes `.jutex/` (with the version history) the first time JuTeX reads it.

Projects stay where they were: if you had `~/LibreTeX`, JuTeX keeps using it as the projects folder. Nothing is deleted before being fully copied, and whatever already exists under the new name is left alone.

On each system:

- **Arch Linux:** the `jutex` package replaces `libretex` when installed.
- **AppImage:** delete the `LibreTeX_…AppImage` and use JuTeX's.
- **macOS:** install JuTeX and drag **LibreTeX** from Applications to the Trash. Two LibreTeX leftovers are no longer used and can be deleted: `~/Library/Caches/org.libretex.app` and `~/Library/Preferences/org.libretex.app.plist`.
- **Windows:** JuTeX's installer doesn't replace LibreTeX's. Install JuTeX, open it once (if LibreTeX is still open, JuTeX asks you to close it and «Retry») and then uninstall LibreTeX from **Settings → Apps**, without ticking «Delete the application data»: if you uninstall it earlier with that box ticked, what the window remembered is deleted (projects and settings aren't).

Where the data lives now: on Linux `~/.config/jutex`, `~/.local/share/jutex` and `~/.cache/jutex`; on macOS `~/Library/Application Support/org.JuTeX.jutex` and `~/Library/Caches/org.JuTeX.jutex`; on Windows `%APPDATA%\JuTeX\jutex` and `%LOCALAPPDATA%\JuTeX\jutex`. They are also shown in **Settings → Paths**.

## What's new since 1.2.2

### On all platforms

- **New name and logo:** JuTeX, with a J instead of the L. The app icon leaves a margin like other apps' icons, so it no longer looks bigger than the rest in the taskbar or the Dock.
- The repository is now [GASDJUGA/jutex](https://github.com/GASDJUGA/jutex) (the old address redirects there).
- The old names still work where they come from outside: the `LIBRETEX_SAFE_RENDERER` variable (now `JUTEX_SAFE_RENDERER`) and the history versions saved by LibreTeX.

## Fixes

- **Linux:** the heading-level selector in the editor toolbar no longer shows up white (with almost invisible text) when the desktop uses a light theme.

## Known issues

- **Linux (WebKitGTK 2.54, NVIDIA):** when coming back to the window, the active line sometimes flickers for a moment (~0.3 s) between the old one and the new one. The page doesn't change: it's the screen.
- **Linux:** when typing an accent with a dead key (´ + o), WebKitGTK shows a frame without the accent or the letter; if the line is right at the edge of the window, it looks like a short jump.
